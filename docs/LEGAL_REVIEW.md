## 1. サービスの概要（前提の共有）

| 項目 | 内容 |
|---|---|
| サービス名 | MasterGame |
| 形態 | スマートフォンアプリ（iOS / Android）＋ Web の運営コンソール |
| 事業モデル | 広告（提携先の成果報酬）を原資に、ユーザーへポイントを付与する、いわゆる**ポイ活** |
| ポイントの入手 | ミッション達成・提携先オファーの達成・連続ログイン・友だち招待・ステーキング |
| ポイントの使途 | **当社が定める商品等との交換のみ**（ゲーム内アイテム、ギフト券等） |
| 換金 | **不可**（現金への交換手段を提供しない） |
| 譲渡・相続 | **不可** |
| 購入 | **ユーザーはポイントを購入できない**（対価を支払って取得する手段が存在しない） |
| 交換レート | 1,000ポイント = 1円相当（`app_config.point_yen_rate`） |
| 有効期限 | 最終利用から12ヶ月（`app_config.point_expiry_months`）。失効30日前に通知 |
| 最低利用年齢 | 13歳（`app_config.min_age`）。18歳未満は保護者同意の案内を表示 |

## 2. 判断していただきたい論点

### 🔴 論点1: 資金決済法上の「前払式支払手段」に該当するか

**最重要の論点です。** 該当する場合、基準日（3月末・9月末）の未使用残高が1,000万円を超えると
**発行保証金の供託義務**等が生じます。

事実関係として実装が保証していること:

- ユーザーは**対価を支払ってポイントを取得できません**（購入導線が存在しない）。
  取得経路はミッション達成・オファー達成・ログインボーナス・招待・ステーキングのみで、
  いずれも**無償**です。
- ポイントは**現金に交換できません**。交換先は当社が定める商品等に限られます。
- 有効期限は最終利用から12ヶ月です。

一般に「対価性がない無償ポイント」は前払式支払手段に該当しないと整理されることが多いと
理解していますが、**この整理で問題ないかの確認をお願いします。** 特に:

1. 広告収益を原資とする付与が「対価の受領」と評価される可能性はあるか
2. ステーキング（残高に応じた上乗せ付与）が性質を変えないか
3. 招待報酬（第三者の行為に基づく付与）が性質を変えないか

**未使用残高は運営コンソールで常時確認できます**（`/economy` の「未交換残高」）。
仮に該当する場合でも、基準日残高の把握と報告は運用可能な状態です。

### 🔴 論点2: 景品表示法上の表示

- 報酬額の表示（「＋1,000P」等）や「もらえる」という表現が、
  **有利誤認・優良誤認**に当たらないか
- 提携先オファーの報酬について「**達成後に提携先の確認を経て確定**する」旨を
  アプリ内に表示していますが、これで十分か
- 連続ログインの段階報酬（7日目に大きく増える設計）の表示方法

### 🔴 論点3: 未成年の利用

- 13歳以上18歳未満の利用を認め、**保護者の同意を得るよう案内を表示**しています。
  同意の**取得方法として十分か**（現状は登録時のダイアログ表示のみで、保護者の
  能動的な同意取得の仕組みは実装していません）
- 未成年によるポイント交換について、追加の制限が必要か

### 🟠 論点4: 個人情報の取扱い

- **不正防止のために端末識別子を保持**し、退会後も保持し続ける設計です
  （「退会 → 再登録」での初回ボーナス荒稼ぎを検知するため）。
  プライバシーポリシーには「不正防止および法令遵守に必要な範囲を除き削除」と記載していますが、
  **この整理と保持期間で問題ないか**
- 生年月日を**年齢確認にのみ**使用し、それ以外に利用しない旨を記載しています
- 退会時に**会計記録（ポイント台帳）と同意記録は保持**します。
  → 詳細は下記「5. 退会時のデータの扱い」

### 🟠 論点5: 利用規約の内容

条文の下書きは `supabase/migrations/0024_legal_and_expiry.sql` に格納しており、
アプリからは `/legal/terms` で表示されます。特にご確認いただきたい条項:

- 第3条（ポイント）… 換金不可・譲渡不可・有効期限・**当社による条件変更権**
- 第5条（不正利用への対応）… **事前通知なくアカウント停止・ポイント取消**ができる旨。
  消費者契約法上、この定めが無効とされないか
- 第6条（免責）… 消費者契約法8条・10条との関係

## 4. 実装が保証していること（レビューの前提として）

条文で約束している内容が、実際にコードで担保されているかの対応表です。

| 規約・PPの記載 | 実装 | 検証 |
|---|---|---|
| 換金・譲渡はできない | 現金化・ユーザー間送付の機能が存在しない | — |
| 有効期限を過ぎたポイントは失効 | `expire_points()` を日次実行。失効も台帳に記録 | `70_legal_test.sql` |
| 失効前に通知する | `notify_expiring_points()`（30日前・重複通知なし） | `70_legal_test.sql` |
| 13歳未満は登録できない | `set_date_of_birth()` が拒否し、**生年月日を保存しない** | `70_legal_test.sql` |
| 生年月日は変更できない | 1度だけ設定可 | `70_legal_test.sql` |
| 規約改定時に再同意を求める | 版を記録し `pending_legal_consents()` が検出 | `70_legal_test.sql` |
| 不正時はアカウント停止・ポイント取消ができる | `resolve_fraud_flag()` / `reverse_postback()` | `40_fraud_test.sql` |
| 退会後は速やかに削除する | `process_account_deletions()`（猶予7日） | `90_deletion_test.sql` |
| 不正防止に必要な範囲は保持する | 端末の紐付けのみ保持。PII は削除/匿名化 | `90_deletion_test.sql` |
| 同意の記録を残す | `legal_acceptances`（誰が・どの版に・いつ） | `70_legal_test.sql` |

## 5. 退会時のデータの扱い（論点4の詳細）

技術的な理由から**物理削除ではなく匿名化**を採用しています。
ポイント台帳が `auth.users` を参照しているため、素朴に削除すると**会計記録ごと消えて**
発行済みポイントの記録・監査証跡が失われるためです。

| データ | 扱い | 理由 |
|---|---|---|
| メールアドレス | 無効化（ログイン不能に） | PII の削除 |
| 生年月日・プロフィール | 削除 | PII の削除 |
| プッシュトークン・興味ジャンル・フォロー・通知 | **物理削除** | 保持する理由がない |
| 保有ポイント | **失効**（台帳に負の記録として残す） | 規約第3条 |
| 投稿・コメント | 残す（投稿者名は「退会したユーザー」に） | 削除するとスレッドが成立しなくなるため |
| **ポイント台帳** | **保持** | 会計記録・監査証跡 |
| **同意記録** | **保持** | いつどの版に同意したかの証跡 |
| **端末の紐付け** | **保持** | 「退会→再登録」での不正の検知 |

**保持期間の定めが必要か**、また**保持している旨のプライバシーポリシー上の記載が
十分か**をご確認ください。
