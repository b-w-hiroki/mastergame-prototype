# プロンプト：プロジェクト資料ハブページを生成する

別のアプリ開発プロジェクトでも、本リポジトリの
[確認ハブ](https://b-w-hiroki.github.io/mastergame-prototype/) と同じ要領で、
散らばった関連資料（プロトタイプ・提案デッキ・仕様書・ロードマップ等）を
**1枚の静的ハブページ**に整理・集約するための、Claude Code 向け再利用プロンプトです。

使い方：対象リポジトリで Claude Code を開き、下の「プロンプト本体」をそのまま貼り付けます。
冒頭の「入力（ここだけ埋める）」を埋めれば、残りはエージェントがリポジトリを走査して自動で組み立てます。
未記入の項目は「リポジトリを調べて推定し、不明なら TODO として残す」よう指示済みです。

---

## 入力（ここだけ埋める）

```yaml
project_name:    "（プロダクト名。例：MasterGame）"
tagline:         "（一言キャッチ。例：遊ぶほど、得をする。）"
one_liner:       "（30〜60字の概要。何のプロダクトか）"
brand:
  monogram:      "（ロゴ用の1〜2文字。例：MG）"
  accent:        "#4f46e5"        # メインのアクセント色
  accent2:       "#7c5cff"        # グラデーション用の副色
  bg_dark:       "#0e1015"        # ヒーロー/テーマカラー
deploy_base_url: "（公開URL。GitHub Pages 等。未定なら空でOK）"
lang:            "ja"
make_pwa:        true              # インストール可能な PWA にするか
```

---

## プロンプト本体（ここから下を貼り付け）

あなたはこのリポジトリの開発資料を整理するシニアフロントエンドエンジニア兼情報設計者です。
このプロジェクトの関連資料を集約した、**単一の静的ハブページ `index.html`** を作成してください。
目的は「プロジェクトに初めて触れる人が、このページから全資料へ迷わず到達できる」ことです。

### ステップ1：リポジトリの資料を棚卸しする

まずコマンド/検索でリポジトリ全体を走査し、次を**実在するものだけ**インベントリ化する
（ハルシネーション禁止。存在しないリンクは作らない）：

- **動作プロトタイプ / 画面**：`*.html`、`wireframes/`、`prototypes/`、Figma リンク等
- **提案資料 / デッキ**：`*.pptx` `*.pdf`、スライド画像群（`slide-*.png` 等の連番）
- **仕様書 / ドキュメント**：`*.md`（`docs/`, `specs/`, `README` 配下）
- **実装の足場**：`apps/`, `src/`, `supabase/`, バックエンド等（あれば「実装」枠で紹介）
- **ロードマップ / フェーズ**：README や docs から MVP・フェーズ表を抽出
- **ライブデモ / 公開URL**：`deploy_base_url` または既存の canonical/OG から推定

各資料について「カテゴリ・タイトル・対象読者・1行説明・リンク（相対パス）」を整理する。

### ステップ2：ハブページを生成する

以下の構成・デザイン言語で、**自己完結した1枚の `index.html`**（CSS はインライン `<style>`、
JS はバニラのインライン `<script>`、外部依存は最小）を生成する。

**レイアウト（上から）**

1. **ヒーロー**：ダーク背景＋アクセント色の放射状グラデーション。左上にモノグラムロゴ＋プロダクト名、
   ステータスチップ（例：稼働中ドット）、`tagline` を大見出し、`one_liner` をサブ、
   主要指標（プロトタイプ数・ドキュメント数など実数）を小さなメタ表示。
2. **カードグリッド**（ヒーローに少し重ねて引き上げる）：プロトタイプ/画面ごとに1カード。
   アイコン・タイトル・対象（ユーザー/運営/企画等）・1行説明・「開く ↗（別タブ）」と
   「このページで見る（ビューア起動）」の2導線。
3. **資料セクション**：仕様書(Markdown)・デッキ(スライド画像/PDF)を一覧化。クリックで
   **ページ内ビューア（モーダル）**を開く：
   - **Markdown ビューア**：`marked` 等で `.md` を取得しレンダリング（取得失敗時は元ファイルへのリンクにフォールバック）。
   - **スライドビューア**：連番画像を左右送り（‹ 前へ / 次へ ›・ドット・**← →キー操作**・カウンタ）。
   - モーダル右上に「元ファイル ↗」リンク。背景クリック／Escで閉じる。
4. **ロードマップ**：抽出したフェーズ表（MVP0→…）をタイムライン/テーブルで表示。
5. **フッター**：プロダクト名・補足・コピーライト（`© {年} {project_name}`。運営会社名は入れない）。

**デザイン言語**

- 配色は `brand.accent` / `accent2` / `bg_dark` を変数化（`:root` の CSS 変数）。
- 角丸・やわらかい影・余白広め・読みやすい行間。ディスプレイ用と本文用でフォントを分ける
  （Web フォントを使う場合は `preconnect`＋`display=swap`、1リクエストに集約）。
- アイコンは SVG シンボル（`<symbol>` 定義→`<use>`参照）でインライン化。
- **完全レスポンシブ**（スマホ1カラム）。`prefers-reduced-motion` を尊重。
- 画像/iframe は遅延読み込み、`alt` を付与。

**技術制約**

- 余計なビルド不要。`index.html` 単体で `file://`／静的ホスティングのどちらでも開ける。
- リンクは**相対パス**（GitHub Pages のサブパス配信でも壊れない）。
- SEO/OGP：`title` `description` `canonical` `og:*` `twitter:*` を設定（`deploy_base_url` があれば絶対URL）。
- アクセシビリティ：見出し階層・キーボード操作・フォーカス可視・コントラスト確保。

### ステップ3（任意）：PWA 化（`make_pwa: true` のとき）

ブラウザからインストール可能・オフライン対応にする：

- `manifest.webmanifest`（name/short_name/icons[192,512,maskable]/`display:standalone`/theme・background color/start_url・scope は相対）。
- `service-worker.js`（App Shell をプリキャッシュ→ナビゲーションは network-first＋`offline.html` フォールバック、静的アセットは stale-while-revalidate）。
- 登録スクリプトは `<link rel="manifest">` の絶対URLからルートを逆算して `service-worker.js` を登録（サブパス/独自ドメイン両対応）。
- アイコンは `brand.monogram` のモノグラムタイル（`accent`→`accent2` グラデ / `bg_dark` 背景）を SVG で作り、PNG（192/512/maskable/apple-touch-icon）へ書き出す。
- 各HTMLの `<head>` に manifest・apple-touch-icon・`theme-color`・`apple-mobile-web-app-*` と登録スクリプトを追加。`.nojekyll` を置く。

### 受け入れ条件（自己チェック）

- [ ] `index.html` を開くと、**実在する**全資料へカード/一覧から到達できる（デッドリンク0）。
- [ ] Markdown／スライドのページ内ビューアが動作し、元ファイルへのフォールバックがある。
- [ ] スマホ幅で崩れない。キーボードのみで主要操作（カード遷移・スライド送り・モーダル開閉）が可能。
- [ ] ロードマップが README/docs の記述と一致している。
- [ ] （PWA時）Lighthouse の Installable 要件を満たす：manifest 解決・SW 登録・アイコン・`start_url` 応答・オフラインでも一度開いた画面が表示。
- [ ] ローカル静的サーバー（例 `python3 -m http.server`）で主要パスが HTTP 200。

### 進め方

1. まず棚卸し結果（カテゴリ別の資料一覧）を**箇条書きで提示**し、構成案を一度共有する。
2. 合意後に `index.html`（＋PWA一式）を生成。
3. ローカルサーバーで配信確認し、デッドリンク・コンソールエラーが無いことを確認。
4. ブランチを切ってコミット＆プッシュし、ドラフトPRを作成。

> 不明・未確定の情報は勝手に創作せず、ページ内に控えめな `TODO:` コメントとして残し、最後に「要確認リスト」として報告すること。
```

## 補足

- このプロンプトは本リポジトリ `mastergame-prototype` の `index.html` を雛形にしています。
  実物を `index.html` で確認し、流用したいコンポーネント（カード/スライドビューア/MDモーダル）を
  そのまま参照させると、より早く同等の品質になります。
- デザインを揃えたい場合は、生成時に「`mastergame-prototype/index.html` のデザイン言語・
  コンポーネント構造を踏襲して」と一言添えると効果的です。
