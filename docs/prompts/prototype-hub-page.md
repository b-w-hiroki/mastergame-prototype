# プロンプト：プロトタイプ専用の資料ハブページを生成する（本番ドメイン分離つき）

**プロトタイプ／資料しか持たないプロダクト**のための、Claude Code 向け再利用プロンプトです。
本リポジトリの[資料ハブ](https://b-w-hiroki.github.io/mastergame-prototype/)と同じ要領で、
プロトタイプ・仕様書・提案資料を **1枚の静的ハブページ** に集約します。

このプロンプトの最重要ポイントは **「本番ドメインとの切り分け」**。
プロダクトの**本番が別ドメインで既に公開済みの場合がある**ため、
ハブ（＝社内・関係者向けの資料/プロトタイプ置き場）が本番サイトと
**SEO・ブランド・PWA・Cookie の面で衝突しない**よう、注意深く設定します。

> フル機能（プロトタイプ＋実装足場＋本番アプリ枠）を1リポジトリにまとめる版は
> `docs/prompts/project-hub-page.md` を参照。本プロンプトは
> **「プロトタイプだけがある／本番は別ドメインで別管理」** のケースに特化しています。

---

## 入力（ここだけ埋める）

```yaml
project_name:    "（プロダクト名）"
tagline:         "（一言キャッチ）"
one_liner:       "（30〜60字の概要）"
brand:
  monogram:      "（ロゴ用の1〜2文字）"
  accent:        "#4f46e5"
  accent2:       "#7c5cff"
  bg_dark:       "#0e1015"
hub_audience:    "internal"        # internal（社内・関係者向け）/ public
hub_host:        "（ハブを配信するホスト。例：proto.example.com / xxx.github.io/repo）"
production:
  status:        "live"            # live（本番が別ドメインで公開済み）/ none（本番未公開）/ separate_repo
  domain:        "（本番ドメイン。例：app.example.com。status=live のとき必須）"
  label:         "本番アプリ（公開中）"
lang:            "ja"
make_pwa:        false             # 既定 false。PWA 化する場合も scope は hub_host 内に限定
```

> **大原則**：`hub_host` は **本番ドメイン（`production.domain`）と必ず別のホスト**にすること。
> 同一・上位・apex が重なる場合は処理を止めて警告する（後述の安全チェック）。

---

## プロンプト本体（ここから下を貼り付け）

あなたはこのリポジトリのプロトタイプ・資料を整理するシニアフロントエンドエンジニア兼情報設計者です。
**プロトタイプと資料だけ**を集約した、**単一の静的ハブページ `index.html`** を作成してください。
これは**社内・関係者向けの確認用ハブ**であり、**一般ユーザー向けの本番画面ではありません**。
本番プロダクトは**別ドメインで別管理**（既に公開済みのこともある）であり、ハブはそれと
**厳密に切り分けて**扱います。

### ステップ0：本番ドメイン分離の安全チェック（最初に必ず実施）

1. `hub_host` と `production.domain` を比較する。**完全一致・サブ/親関係・同一 apex（例 `example.com` と `www.example.com`）**の場合は、
   **生成を中断し**「ハブは本番と別ホストに分けてください」と警告して指示を仰ぐ。
2. リポジトリ内に本番サイトを示す痕跡（既存の `CNAME`＝本番ドメイン、本番URLを指す `canonical`/`og:url` 等）がないか走査。
   見つかったら **流用しない**（後述のとおり canonical/OG はハブ自身のURLに向ける）。
3. 既存の `CNAME` が本番ドメインを指しているなら、それは本番用。ハブ用には**別の専用ホスト**を使う（apex/www は使わない）。

### ステップ1：リポジトリの資料を棚卸しする

実在するものだけをインベントリ化（ハルシネーション禁止・デッドリンク厳禁）：

- **動作プロトタイプ / 画面**：`*.html`、`wireframes/`、`prototypes/`、Figma 等
- **提案資料 / デッキ**：`*.pptx` `*.pdf`、スライド画像群（連番）
- **仕様書 / ドキュメント**：`*.md`
- **ロードマップ / フェーズ**：README/docs から抽出
- **本番への参照**：`production.status` と `production.domain`（**リポジトリ内の資産ではなく外部リンク**として扱う）

### ステップ2：ハブページを生成する

**自己完結した1枚の `index.html`**（CSS インライン、JS バニラ、外部依存は最小）。

**レイアウト（上から）**

1. **ヒーロー**：ダーク背景＋アクセント色グラデ。モノグラムロゴ＋プロダクト名。
   - ステータスチップに立て付けを明記：`internal` なら「社内・関係者向け資料ハブ ・ 一般ユーザー向けの画面ではありません」。
   - 見出しは「{project_name} の**プロトタイプ／資料**ハブ」。本番そのものと誤認されない文言にする。
   - サブ文に「**本番は別サイト**（{production.label}）。ここは確認用のプロトタイプ・資料です」。
2. **Prototypes（確認用）**：プロトタイプ/画面をカード化。見出しは「Prototypes（確認用）」、
   「画面・導線の確認用です。本番サイトではありません」と注記。各カードは別タブで開く＋必要ならページ内ビューア。
3. **Production（本番・別ドメイン）リンクブロック**：プロトタイプとは**別ブロック**で明確に分離。
   - `production.status: live` → 「{production.label} ↗」を **本番ドメインへの絶対URL**で配置。
     `target="_blank" rel="noopener noreferrer"`。`https://{production.domain}` を明示表示し、**別サイトへ出る**ことが分かるUI（外部リンクアイコン等）にする。
   - `production.status: none` → 「本番：準備中」プレースホルダ。
   - `production.status: separate_repo` → 「本番は別リポジトリ/別管理」と明記（URLがあればリンク）。
   - **本番を iframe で埋め込まない**。ハブの一部であるかのように見せない。
4. **資料セクション**：Markdown はページ内ビューア（`marked` 等、失敗時は元ファイルへフォールバック）、
   デッキは連番画像の左右送り（‹/›・ドット・←→キー・カウンタ）。モーダル右上に「元ファイル ↗」。
5. **ロードマップ**：抽出したフェーズ表。
6. **フッター**：`© {年} {project_name}`（運営会社名は入れない）。

**デザイン言語**：配色を `:root` 変数化、角丸・やわらかい影・余白広め、SVGシンボルアイコン、
完全レスポンシブ、`prefers-reduced-motion` 尊重、画像は遅延読み込み＋`alt`。
**確認用（プロトタイプ）と本番（外部リンク）が一目で別物**と分かる差をつける。

### 本番ドメインとの切り分け（技術設定・最重要）

- **ホスト分離**：ハブは `hub_host` のみで配信。**本番ドメイン（apex/www）には絶対に載せない**。
- **検索エンジン**：ハブは**全ページに `<meta name="robots" content="noindex, nofollow">`**、
  `robots.txt` は `Disallow: /`、`sitemap.xml` は作らない。
  → 本番サイトの検索順位・ブランド表記とハブが**競合しない**ようにする（重複コンテンツ回避）。
- **canonical / OG**：
  - `canonical` と `og:url` は**ハブ自身のURL（`hub_host`）**に向ける。**本番ドメインを指さない**（誤った正規化・流入の取り違えを防ぐ）。
  - `og:title` 等にも「[プロトタイプ]／[資料]」の識別子を付け、本番の見え方と区別する。
- **本番へのリンク**：常に**絶対URLの外部リンク**（`https://{production.domain}`）＋`rel="noopener noreferrer"`＋別タブ。相対パスで本番を指さない。
- **PWA（任意）**：`make_pwa: true` でも **manifest の `scope`/`start_url` は `hub_host` 配下に限定**。
  Service Worker の登録スコープもハブ配下のみ。**本番ドメインの URL を manifest に含めない**（本番アプリと競合する PWA を作らない）。
- **Cookie / 解析**：Cookie を**親ドメイン（`domain=.example.com`）に設定しない**（本番とまたがせない）。
  解析を入れるなら**ハブ専用プロパティ**にし、本番の計測に混ぜない。
- **カスタムドメイン**：使う場合も `proto.` などの**専用サブドメイン**。本番 apex/www へ向ける `CNAME` を作らない。

### ステップ3（任意）：PWA 化（`make_pwa: true` のとき）

`manifest.webmanifest` / `service-worker.js`（App Shell プリキャッシュ＋`offline.html`）/
`<link rel="manifest">` から逆算した登録スクリプト / モノグラムアイコン（PNG 192/512/maskable/apple-touch）/
各HTMLへ `theme-color`・`apple-mobile-web-app-*`・`.nojekyll`。
**ただし scope/start_url・SW スコープは `hub_host` 配下に限定**（本番側の PWA とぶつけない）。

### 受け入れ条件（自己チェック）

- [ ] **本番ドメイン分離**：`hub_host` ≠ `production.domain`。canonical/og:url がハブ自身を指し、**本番ドメインを指していない**。
- [ ] 本番へのリンクは**外部・別タブ・`rel="noopener noreferrer"`**で、iframe 埋め込みをしていない。
- [ ] 全ページに `noindex`、`robots.txt` が `Disallow: /`、`sitemap.xml` が無い。
- [ ] ハブが**社内・関係者向けのプロトタイプ/資料ハブ**であり、**本番画面ではない**ことがヒーローで明示されている。
- [ ] Prototypes（確認用）と Production（本番・別ドメイン）が別ブロックで明確に分離されている。
- [ ] 実在資料へデッドリンク0で到達できる。Markdown/スライドのビューアが動作（失敗時フォールバックあり）。
- [ ] スマホで崩れず、キーボードのみで主要操作が可能。
- [ ] （PWA時）manifest の scope/start_url・SW スコープが `hub_host` 配下に限定され、本番URLを含まない。
- [ ] ローカル静的サーバーで主要パスが HTTP 200（`sitemap.xml` は 404）。

### 進め方

1. **ステップ0の安全チェック結果**（hub_host と本番ドメインの分離可否）をまず報告する。
2. 棚卸し結果（プロトタイプ／資料の一覧。本番は外部リンクとして区別）を箇条書きで共有し、構成案を提示。
3. 合意後に `index.html`（＋任意で PWA一式・robots.txt）を生成。
4. ローカルサーバーで配信確認（デッドリンク・コンソールエラー・本番への相対リンク混入が無いこと）。
5. ブランチを切ってコミット＆プッシュし、ドラフトPRを作成。

> 不明・未確定（特に本番ドメイン）の情報は創作せず、`TODO:` コメントとして残し、最後に「要確認リスト」で報告すること。
> **本番ドメインが不明なときは、本番リンクを「準備中」にして勝手にURLを作らない。**

## 補足

- 立て付けの要点：**ハブ＝社内向けのプロトタイプ/資料置き場（noindex・別ホスト）／本番＝別ドメインの公開サイト（外部リンクのみ）**。
- デザインを揃えたい場合は「`mastergame-prototype/index.html` のデザイン言語・コンポーネント構造を踏襲して」と添える。
- フル実装（実装足場・本番アプリ枠を同居）に発展させる場合は `docs/prompts/project-hub-page.md` に乗り換える。
