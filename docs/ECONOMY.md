# ポイント経済設計（レートカード）

MasterGame のポイント経済の設計根拠。インタラクティブ版は
**[ポイント経済シミュレーター](https://b-w-hiroki.github.io/mastergame-prototype/wireframes/economy.html)**（`wireframes/economy.html`）。

## 基本レート

- **1,000P = 1円**（`app_config.point_yen_rate = 1000`）
- 実質価値は**換金性のある交換先（ギフト券）でアンカー**：Amazon 500円 ＝ 500,000P
- デノミ（表示倍率）はUX選択。実質価値を保てば自由にスケールできる

## 単価の決め方（2層モデル）

| 層 | 対象 | 単価の決め方 |
|---|---|---|
| **広告/オファー（収益連動）** | 動画リワード・提携オファー・課金・アンケート | **推奨単価P ＝ 収益/回 × 還元率 × レート** |
| **エンゲージ（固定予算）** | 記事閲覧・X視聴・ログインボーナス | 収益に直結しない**継続のための予算**として単価を直接設定 |

- **還元率（payout ratio）**：広告収益のうちユーザーへ還元する割合。標準 **50%**（保守35%〜積極65%）。
- `app_config.payout_ratio_bps = 5000`（= 50%）

## 収益ベンチマーク（日本・概算レンジ）

> ネットワーク・時期・地域で大きく変動。実運用では各ネットワークの実績値に置換。

| アクション | 収益/回（目安） | 種別 |
|---|---|---|
| 動画リワード視聴 | eCPM ¥1,500〜3,000/1000 ＝ **¥1.5〜3/回** | 広告 |
| オファー：インストールCPA | ¥150〜300 | オファー |
| オファー：初回課金 | レベニューシェア（¥500〜2,000） | オファー |
| アンケート回答 | ¥50〜150 | オファー |
| バナー/記事内広告 | eCPM ¥300前後 ＝ ¥0.3〜1/回（間接） | エンゲージ |

## 推奨レートカード（還元率50%・1,000P=1円）

| アクション | 収益/回 | 種別 | 推奨単価 | （現行プロトタイプ） |
|---|---|---|---|---|
| 動画リワード視聴 | ¥2.0 | 広告 | **1,000P** | 500P（25%＝保守的） |
| インストールオファー | ¥300 | オファー | **150,000P** | 80,000P（27%＝保守的） |
| 初回課金オファー | ¥800 | オファー | **400,000P** | 500,000P |
| アンケート回答 | ¥100 | オファー | **50,000P** | 12,000P |
| 攻略記事を読む | ¥1.0(間接) | エンゲージ | 固定予算 **3,000P** | 3,000P |
| 公式Xを見る | ¥0.6(間接) | エンゲージ | 固定予算 **2,000P** | 2,000P |
| ログインボーナス | — | エンゲージ | 固定予算 **1,000P** | 1,000P |

→ プロトタイプは広告/オファー系を**保守的**（還元率低め）に設定。アンケートは還元を上げる余地が大きい。
シミュレーターで還元率を動かして粗利とのバランスを確認できます。

## 配布構造：額面 ≠ 実コスト（真の粗利）

ポイントを付与した「額面（¥換算）」と、MasterGame が実際に負担する「実コスト」は別物です。

```
配布(額面) ──┬─ ゲームアイテム交換 … 原価率 低（提携先提供 ≒15%）
             ├─ ギフト券交換       … 原価率 ≒100%（現金等価）
             └─ 未交換(breakage)   … 原価 0（失効・滞留）

実配布原価 ＝ 配布額面 × Σ(交換先ミックス × 原価率)
真の粗利   ＝ 広告収益 − 実配布原価
```

| | 額面ベース（保守） | 真の粗利（実原価ベース） |
|---|---|---|
| 計算 | 収益 − 配布額面 | 収益 − 実配布原価 |
| 例（mix: アイテム70%/ギフト20%/未交換10%、原価率15%/100%/0%） | 粗利 ¥140,000（30%） | **粗利 ¥362,400（79%）** |

差（30%→79%）の正体は **①提携アイテムの低原価（アフィリエイトモデルの強み）＋②breakage**。
**現金等価（ギフト券）比率が上がるほど真の粗利は縮む**（例：ギフト60%にすると 79%→55%）。
→ ギフト券はあえて割を悪くしてアイテム交換へ誘導するのが定石。

スキーマ：`exchange_items.cost_rate_bps`（交換先の実原価率）、`app_config` の `redemption_mix_*`（交換先ミックス）。

## P&L 例（DAU 10,000・還元率50%）

- 日次 広告収益 ≈ **¥460,000**（ARPDAU ¥46）
- 日次 ポイント付与 ≈ **¥320,000**（1人 ¥32/日）
- 日次 粗利 ≈ **¥140,000**（粗利率 ≈ 30%／運営固定費・決済手数料は別途）

> アンケート（¥15/人）とエンゲージ系（¥9/人）が付与コストの大半。
> 収益連動の単価は還元率で、エンゲージ系は予算上限で管理するのが要点。

## 設計レバー

1. **現金等価（ギフト券）はあえて割を悪く** → アイテム交換へ誘導しマージン保護（限定アイテムは原価低・高マージン）
2. **エンゲージ系は固定予算** → 継続率への投資として上限管理（ROIは継続率/LTVで評価）
3. **レートは1か所**（`app_config.point_yen_rate`）で変更 → 全体に反映
4. **XPはポイントと分離**（`missions.xp_reward`）→ 単価を変えてもVIP進行は不変
