# MasterGame MVP 実行計画

更新日: 2026-09-19

## 1. 目的

最小の価値ループを、利用者操作から運営確認まで実データで一周させる。

```text
ログイン
  → オファー開始
  → click_id 発行
  → 成果 postback
  → ポイント付与
  → 残高確認
  → 報酬交換申請
  → 管理画面で確認
```

## 2. 今回のスコープ

### 必須

- メールログイン
- 検証用オファー1件
- `track_click` による click ID 発行
- click ID を含む外部遷移
- HMAC 署名付き postback
- 署名、帰属、期限、重複の検証
- ポイント台帳と残高更新
- 検証用交換アイテム1件
- 交換申請
- 管理画面での postback と交換申請確認
- 中核フローの再現可能なテスト

### 今回は対象外

- 実広告ネットワーク SDK
- 実際のギフトコード配送
- VIPランク改善
- ステーキング改善
- コミュニティ改善
- Push通知
- ナッジの高度化とA/Bテスト
- 画像生成と追加デザイン調整
- App Store / Google Play 公開

対象外機能は削除せず、MVP の完了判定から外す。

## 3. 暫定検証データ

| 項目 | 暫定値 |
|---|---|
| 認証 | メールアドレス＋パスワード |
| 広告パートナー | `test-partner` |
| オファー | 検証用オファー達成 |
| オファー報酬 | 500,000P |
| レート | 1,000P = 1円 |
| 交換商品 | 検証用デジタルギフト500円分 |
| 必要ポイント | 500,000P |
| 配送 | 実配送なし、交換申請の記録まで |

この値は実装を止めないための暫定値であり、外部パートナー接続前に変更できる。

## 4. 技術的な受け入れ条件

### オファー開始

- ログインユーザーだけがオファーを開始できる。
- タップごとに推測困難な click ID が発行される。
- 外部URLへ click ID が渡される。
- 連打しても不要な複数遷移を起こさない。

### postback

- 正しいHMAC署名の成果だけを受理する。
- 不正署名を拒否する。
- 未知のパートナーを拒否する。
- 存在しない、または期限切れの click ID を拒否する。
- 同じ transaction ID では一度だけ処理する。
- 同じ click ID に対する複数付与を防ぐ。
- BAN・凍結ユーザーには付与しない。
- 受理、拒否、重複の結果が記録される。

### ポイント

- postback受理後に台帳へ1件だけ記録される。
- 台帳合計とウォレット残高が一致する。
- ミッション完了状態が `confirmed` になる。
- モバイル画面を更新すると新残高が表示される。

### 交換

- 残高不足では申請できない。
- 在庫切れまたは非公開商品は申請できない。
- 成功時にポイントが一度だけ減る。
- 交換申請とポイント台帳を追跡できる。
- 管理画面で申請を確認できる。

### 管理画面

- 一般ユーザーはアクセスできない。
- service roleキーはブラウザへ送信されない。
- 主要操作がサーバー側でも認可される。

## 6. 計測項目

- オファー表示数
- オファー開始数
- click ID発行成功率
- postback受信数
- accepted / duplicate / rejected の内訳
- ポイント付与成功率
- 初回交換申請率
- 各工程のエラー数
- 1成果あたり収益、ポイント額面、想定実原価

初回テストでは合否の数値を先に作り込みすぎず、離脱地点と技術的失敗を発見する。外部パートナー接続前に継続判断基準を設定する。

## 7. 外部入力が必要な地点

次の項目だけはユーザーまたは外部サービスの操作が必要になる。

- Docker Desktopを導入するか、クラウドSupabaseを使うかの選択
- クラウドSupabaseを使う場合のプロジェクト作成
- 秘密鍵・環境変数のローカルまたはホスティング環境への登録
- Vercel、OAuth、広告ネットワーク等へのログイン
- 外部公開の最終承認
- クローズドテスト参加者の募集

秘密値はリポジトリへ保存しない。

## 8. 実装原則

- 既存の未コミットUI変更を保護する。
- ポイント更新は必ずRPCと台帳を経由する。
- モバイルからservice roleを使用しない。
- テスト用機能を本番で有効にしない。
- 手作業で一周できるまで外部SDKや高度な自動化を追加しない。
- 各Phaseの終了時に型チェックと差分確認を行う。
