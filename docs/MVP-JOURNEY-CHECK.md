## 1往復の観察記録
各段階で対象コミット、時刻、アカウントの匿名ラベル、画面結果、台帳・申請IDを記録。失敗時は成功に補完せず停止する。

1. 登録・ログイン → 初期残高と本人を確認。メール/OAuthの未確認を分離。
2. ミッション1件 → 画面報酬と台帳付与が一致。連打で二重付与しない。
3. 再読込 → 残高と達成済み表示を保持。
4. 架空商品の交換申請 → 減算、履歴、在庫が一致。結果不明なら再申請せず履歴確認。
5. テスト運営者の処理 → 履行状態、通知、本人の履歴が一致。
6. 別アカウントへの切替 → 前の残高・コードを表示しない。
7. 通信失敗と復帰 → 取得失敗が0Pや正常0件にならず、再試行で正しいデータを表示。

既存の supabase/tests/20_economy_test.sql と画面テストは補助であり、実環境確認の代替ではない。後片付けは隔離環境の既定手順を使い、本番データを削除しない。

## 採否
証拠が揃うまで公開・運用確認済みとしない。失敗段階だけ再現して修正し、不明な交換を盲目的に再送しない。今回アプリ・DB実装を変えていないため、現行機能仕様・技術設計への意味変更はない。
